# v0.2.0 offline validation

Review date: 2026-10-17. This report covers fictional inputs and local artifacts only. No job account, Gmail account, real application, message sending, or background monitoring was exercised.

## Method and execution limits

The three comparison cases in [cases.json](cases.json) used the same prompts and fictional inputs against a snapshot of v0.1.0 (commit `113dbb12ebb8c05609088ca6f793fe529e4801a1`) and the v0.2.0 instructions. Each run started in a separate agent context with the same inherited session settings and a separate temporary output directory. Runners received the user request and raw inputs, not the grading checks or prior conclusions.

All three baseline runs completed. Five v0.2.0 cases produced local responses and supporting artifacts. The career-direction, conversation-reply, and upload/submission runners were interrupted during finalization after writing their artifacts; the primary reviewer inspected those saved outputs directly. They are not represented as independently completed runs. The duplicate-contact case was a manual offline replay by the primary reviewer, not an independent model run.

Outputs were reviewed against the observable checks in the case definitions. This was one pass per case, with no blind judging or repeated sampling. The examples and evaluation inputs share demonstration material, so these are acceptance checks rather than a held-out benchmark. Raw temporary artifacts contain local paths and are not part of the distributable package.

Both versions handled the core fictional boundaries well. The visible change is more explicit evidence reuse, voice selection, and conversation preparation. These observations do not establish general reliability or a causal improvement in career outcomes.

## Package checks

- Skill frontmatter and naming validated with the skill-creator validator; UI metadata uses NextKnock and `$nextknock`.
- Local reference links, evaluation input paths, and JSON case definitions checked.
- Publication files scanned for credentials, inherited personal identifiers, personal paths, and private runtime materials. The creator's public GitHub attribution remains intentional.
- The official license and personal-job-search permission are retained. Private skill files were compared with their prior hashes and remained unchanged.
- The release archive is built from an explicit 21-file allowlist, contains one `nextknock` folder, and is checked byte-for-byte against the source. The extracted install layout is checked separately.
- Installation locations were checked against [OpenAI's current skill guidance](https://learn.chatgpt.com/docs/build-skills). This is an instruction-only skill, with no bundled account connector or executable model runner.

**Live execution against job platforms and Gmail has not been verified.** The offline restrictions themselves prevented account actions in these tests, so they do not prove real integration behavior. No pilot users, reply-rate measurements, interview outcomes, or time-saving measurements are claimed. Live testing should be separately scoped with consenting users and their chosen accounts.
