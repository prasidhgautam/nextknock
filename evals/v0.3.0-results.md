# v0.3.0 LinkedIn workflow validation

Review date: 2026-10-18. Inputs, candidates, companies, profiles, receipts, and events were synthetic. No real LinkedIn, Gmail, employer/ATS, invitation, message, credit, or scheduler operation was performed.

## Method

The eight cases in [linkedin-cases.json](linkedin-cases.json) used the separate [raw state packet](linkedin-state.md). It contains observations and capability restrictions rather than expected decisions. Candidate/company material differs from the existing outreach instruction examples; executing agents were not given the public walkthrough, grading checks, other versions, or intended answers.

Three fresh evaluator contexts executed groups of two or three cases each using the same inherited session settings. They were instructed to isolate variants and use separate output folders; complete context isolation between cases within a group is not established. A fourth fresh context executed a targeted retest after one correction. The primary reviewer inspected actual answers and supporting records against 44 observable checks across the eight cases. A separate source-review agent reviewed workflow consistency and reported no blocking findings before the targeted clarification; the primary reviewer inspected that clarification afterward.

This is a single-pass acceptance exercise with one targeted rerun, not a blind comparison, repeated benchmark, or proof of reliability. The previous six general cases were not rerun; [v0.2.0 results](v0.2.0-results.md) remain historical. Runtime outputs stayed outside the installed skill and public package.

All 44 checks were satisfied in the final reviewed outputs after the one targeted correction. These are observed results for these fixtures, not an accuracy estimate. The behavioral agents used sequential role checklists for their small tasks; the source review and implementation responsibilities were separately delegated. The tests do not establish a functioning distributed runtime or live integration.

## Structure and publication checks

- Skill frontmatter, naming, UI metadata, JSON case definitions, and local references validated.
- Sources checked against LinkedIn's current [automation restriction](https://www.linkedin.com/help/linkedin/answer/a1341387), [InMail guidance](https://www.linkedin.com/help/linkedin/answer/a546814), and [personalized invitations guidance](https://www.linkedin.com/help/linkedin/answer/a563153). Feature/credit/character limits remain account-dependent observations, not hard-coded entitlements.
- LinkedIn site actions default to manual completion; no permitted LinkedIn integration is bundled. The imaginary test stub cannot authorize any real operation.
- Release contents use an explicit 28-file allowlist, one installable `nextknock` folder, byte-for-byte archive checks, an extracted installation check, and checksum generation. The license and personal-job-search permission remain unchanged.
- Publication files scanned for credentials, inherited personal identifiers/paths, private candidate materials, and runtime state. Existing private career/outreach skill files were compared with a pre-change hash snapshot.
- Installation paths checked against [current OpenAI skill guidance](https://learn.chatgpt.com/docs/build-skills). The package contains no scheduler, account access, or extra installed subskills; delegation and watches depend on the host's actual capabilities.

**Live platform execution, live scheduling/expiration, concurrent locking, integration permissions, and delivery have not been verified.** Offline restrictions themselves prevent external actions in these tests. No reply-rate, interview, employment, or error-free-operation guarantee is claimed. Scheduled watching needs a separately configured permitted source and supported scheduler; event/interval latency means instant detection cannot be promised.
